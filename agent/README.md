# Бот управления ежедневной настройкой Gift Satellite

Отдельный проект Vercel с корнем `agent`, только в ветке `experiment/gift-satellite-api`. Основной Mini App не изменяется. Ежедневный Cron: 06:00 UTC (09:00 Москва; Hobby запускает в пределах часа). Команды `/start`, `/status`, `/report`, `/pause`, `/resume`; Telegram-клавиатура с теми же командами. Отчёты отправляются владельцу даже при паузе.

Реализованы webhook с проверкой секрета Telegram, доступ только владельцу в личном чате, постоянное состояние Upstash Redis, подавление повторных/устаревших управляющих команд и параллельных ежедневных запусков. Начальное состояние — пауза. Сбой хранилища запрещает изменение цен. Блокировка ежедневного запуска действует 10 минут: будущая функция торговли должна укладываться в это время; иначе требуется продление аренды.

`/pause` останавливает последующие изменения лимитов, но не отменяет уже отправленный запрос и НЕ выключает существующую автопокупку Gift Satellite. Бот явно сообщает об этом. Для остановки самих покупок требуется отдельный подтверждённый метод API провайдера.

## Что ещё не подключено

Ключ API существует в исходном приложении, но его методы и права изменения слотов не установлены. Адаптер Gift Satellite отсутствует: ежедневный обработчик отправляет честный статус «API ещё не подключён», не обращается к рынку и не меняет слоты. `dailyReport` принимает будущую функцию `run({ beforeWrite })`; она обязана проверять `beforeWrite` непосредственно перед КАЖДЫМ запросом изменения. Это интерфейс подключения, а не работающая интеграция рынка. Покупок и продаж в проекте нет.

6 октября 2026 создан отдельный бот `@GiftPriceControl812_bot` (Gift Price Control) через BotFather. Токен оставлен в Telegram, не перенесён в файлы или Git. Не установлен webhook, не создан Redis и не опубликован проект. Один токен не должен обслуживаться двумя независимыми обработчиками обновлений.

## Первоначальная настройка

1. Бот `@GiftPriceControl812_bot` уже создан. Его токен добавить только в секрет `CONTROL_BOT_TOKEN` Vercel, не в Git и не в переписку.
2. `CONTROL_OWNER_ID` — числовой Telegram ID владельца. Хранилище — Upstash Redis REST; добавить URL и токен из его панели в одноимённые переменные из `.env.example`.
3. Сгенерировать разные случайные секреты для `CRON_SECRET` и `TELEGRAM_WEBHOOK_SECRET`. Установить Telegram `setWebhook` на `https://<домен>/api/telegram`, указав `secret_token`, `allowed_updates: ["message"]`. Проверить через `getWebhookInfo`. Эти действия из кода не выполнялись.
4. Написать `/start` выбранному боту, проверить `/status`, `/pause`, `/resume`. До подключения API последний пункт не меняет цены.
5. Подключить документированные методы провайдера, проверить расчёт без записи, затем отдельно включить запись. Нужны текущие цены/продажи, свои слоты, обновление лимита, фактические комиссии и права ключа. Ценовые правила находятся в `server/pricing.js`; они сами API не вызывают.

Хранилище содержит состояние паузы и последний отчёт. Секреты не возвращаются из HTTP-обработчиков и не записываются в сообщения. При сбое отправки отчёта возможна повторная доставка; точно однократную доставку Telegram Bot API не гарантирует. Cron автоматически повторные попытки не планирует: ошибки нужно отслеживать при развёртывании.

Проверка: `node --test agent/control.test.js`. Тесты используют поддельный провайдер/хранилище, не сеть и не деньги.

Документация: https://core.telegram.org/bots/api#setwebhook · https://upstash.com/docs/redis/features/restapi · https://vercel.com/docs/cron-jobs/usage-and-pricing
